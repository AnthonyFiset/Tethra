# M5.5 — Local terminal, identity, and interface polish

_A consolidation pass between M5 and M6. Four tracks, ordered by risk._
_Authoritative rules remain [`PROJECT.md`](../PROJECT.md); this doc adds one
platform trait to §5 and removes "local shell" from the implicit out-of-scope list._

**Do track A first.** It is the only one that can destroy user data, and doing it
before the UI work means the rename doesn't have to be threaded through new files.

---

## Track A — Rename to Tethra

### A0. Audit the identity-derived paths first ⚠️

`tethra-tauri` → `tethra` is cosmetic. Changing the **bundle identifier** is not.
Two things are almost certainly keyed off it:

1. **The keyring entry** holding vault recovery material
   (`crates/platform-desktop`, via `keyring::Entry::new(service, user)`).
2. **`AppPaths::data_dir()`**, which is where the SQLite vault lives.

If either derives its name from the bundle identifier or the crate name, renaming
silently orphans the existing vault: the app starts clean, the old data is still on
disk but unreferenced, and the recovery key is in a keychain entry nothing reads.

**Before changing anything**, grep for how those two strings are built:

```bash
rg -n 'Entry::new|keyring::|service|identifier' crates/platform-desktop/src
rg -n 'data_dir|app_data_dir|bundle' crates/platform-desktop/src apps/tauri/src-tauri/src
```

**Required outcome:** preserve the already-shipped values and expose them as
hard-coded constants that never change again. They must remain independent of
package name, product name, or future cosmetic renames. The recovery key account
name in `core` is also permanent.

```rust
// crates/platform-desktop/src/lib.rs
pub const KEYRING_SERVICE: &str = "app.tethra.desktop";
pub const APP_DIR_NAME: &str = "tethra";

// crates/core/src/vault/store.rs — never rename without migration.
pub const RECOVERY_SECRET_KEY: &str = "ssh-client.vault.recovery-key";
```

The current production values already match these constants, so **do not add a
new migration and do not change letter case**. Existing migrations from
`dev.sshclient.desktop` and `ssh-client` remain in place. Add tests asserting the
literal values so any future identity change fails loudly in CI.

### A1. Crate and package names

| Location | From | To |
|---|---|---|
| `apps/tauri/src-tauri/Cargo.toml` `[package] name` | `tethra-tauri` | `tethra` |
| `tauri.conf.json` `productName` | — | `Tethra` |
| Cargo `[[bin]] name` | `tethra-tauri` (implicit) | `tethra` |
| `tauri.conf.json` `identifier` | `app.tethra.desktop` | keep unchanged permanently |
| `apps/ui/package.json` `name` | — | `tethra-ui` |
| Window title / About panel | — | `Tethra` |
| macOS `CFBundleName` / `CFBundleDisplayName` | — | `Tethra` |

### A2. Set up the mobile lib target now

M11 needs a `cdylib` for iOS. Doing it during the rename avoids renaming twice:

```toml
[lib]
name = "tethra_lib"
crate-type = ["staticlib", "cdylib", "rlib"]

[[bin]]
name = "tethra"
path = "src/main.rs"
```

Move the builder into `lib.rs` behind `#[cfg_attr(mobile, tauri::mobile_entry_point)]`
and reduce `main.rs` to a call into it.

### A3. Update the CI script

`cargo test -p tethra-tauri` → `cargo test -p tethra` in both places
(including the `export_bindings` invocation) and in `STATUS.md`.

**Acceptance:** full CI-equivalent passes; launching the renamed build on a machine
with an existing vault unlocks with the existing master password and shows all hosts.

## Track B — Local terminal

### B0. Where this is allowed to live

Spawning a process is a platform API, so it cannot go in `core` (hard rules 1–2),
and iOS cannot spawn processes at all. This follows the exact shape `HardwareKey`
already uses: trait in `platform`, real impl in `platform-desktop`, `Unsupported`
in `platform-ios`.

> **Do not use `tauri-plugin-pty`.** It exposes a PTY API directly to JavaScript,
> which puts process spawning in the frontend and bypasses the platform boundary.
> It's the fast path and it's the wrong one.

### B1. New platform trait

```rust
// crates/platform/src/local_pty.rs
pub struct ShellSpec {
    pub program: PathBuf,
    pub args: Vec<String>,
    pub cwd: Option<PathBuf>,
    pub env: Vec<(String, String)>,
}

pub trait LocalPty: Send + Sync {
    fn is_available(&self) -> bool;
    fn default_shell(&self) -> Option<ShellSpec>;
    // Output receiver has one owner, matching SessionManager::open_pty.
    fn spawn(&self, spec: ShellSpec, size: PtySize)
        -> Result<(Box<dyn LocalPtySession>, mpsc::Receiver<Bytes>)>;
}

pub trait LocalPtySession: Send {
    fn write(&mut self, data: &[u8]) -> Result<()>;
    fn resize(&mut self, size: PtySize) -> Result<()>;
    fn close(self: Box<Self>) -> Result<()>;
}
```

Add `LocalPty` to the trait list in `PROJECT.md` §5.

### B2. Desktop implementation

Use `portable-pty` (wezterm's) — one API across macOS, Linux, and Windows ConPTY,
with SIGWINCH-equivalent resize and cloneable readers.

`portable-pty` is blocking. Its reader, writer, resize, kill, and wait operations
must run on dedicated worker threads / a command loop; never block Tokio's async
workers and never use `spawn_blocking` once per keystroke. Drop the slave after
spawning so EOF propagates correctly.

**Shell resolution:**

- macOS: `$SHELL` → `getpwuid` → `/bin/zsh`
- Linux: `$SHELL` → `getpwuid` → `/bin/bash`
- Windows: `pwsh.exe` on PATH → `powershell.exe` → `cmd.exe`

**Environment:** set `TERM=xterm-256color`, `COLORTERM=truecolor`, and
`TETHRA=1` so users can branch in their rc files. On macOS, spawn as a **login
shell** (`-l`) on first launch or the GUI process's `PATH` won't include anything
from `.zprofile` — this is the classic "works in Terminal.app, not in my Electron
app" bug and it will be the first thing you hit.

**Windows caveat:** upstream `portable-pty` does not pass the newer ConPTY
creation flags — `PSEUDOCONSOLE_WIN32_INPUT_MODE` and `PSEUDOCONSOLE_PASSTHROUGH_MODE`
— which affect key handling and VT sequence relay on Windows 10/11. Expect minor
key/cursor-shape quirks there; if they bite, a patched fork exists as prior art.
Not a blocker for M5.5.

### B3. Generalize the session model

Sessions are currently SSH-keyed by `host_id`. Introduce a source discriminant in
the Tauri layer and route on it:

```rust
enum TerminalSource {
    Local { shell: Option<String>, cwd: Option<PathBuf> },
    Ssh   { host_id: Uuid },
}
```

**Reuse the M2 output pump.** If the ~10ms batching and backpressure logic is
currently welded to SSH sessions, extract it into a shared `OutputPump` that both
sources feed. Local shells produce output faster than SSH ever will — `cargo build`
on a big workspace is a harder throughput test than anything over the network — so
this is the layer that already solves it.

### B4. Two behavioural decisions

**Vault lock must not kill local sessions.** Today lock cancels transfers and
closes PTY sessions. A local shell is not vault-derived, and killing someone's
running build because of a five-minute idle timer is hostile. Local sessions
survive lock; the lock screen covers them visually. SSH sessions keep current
behaviour.

**Route local exec through `ApprovalGate`** (`PROJECT.md` §9). It's still a no-op,
but "the agent ran something on my laptop" is a worse outcome than "the agent ran
something on a server," so the call site needs to exist before the agent does.

**Acceptance:** new local tab opens the user's real shell with correct `PATH`;
`vim`, `htop`, and `tmux` render and accept input; resize reflows; `cargo build`
output doesn't stutter; closing the tab reaps the child; vault lock leaves it running.

## Track C — Interface

### C0. Direction

The terminal is already the most colourful thing on screen. So the chrome's job is
to **recede** — near-monochrome, one accent, minimal physical footprint. Avoid the
default terminal-app look (near-black plus one acid-green accent); it's the pattern
every AI-styled devtool lands on and it fights the ANSI palette underneath.

**Signature element — host colour as ambient identity.** `Host.color` exists in
the encrypted model but is not yet exposed by `HostSummary`, IPC, or the editor.
Wire that full data path first, then show the colour as the collapsed sidebar rail
indicator, active tab underline, and a 1px hairline along the top of the terminal
viewport. You know which machine you're on peripherally, without reading a label.
This is a real safety property for anyone who has ever run a destructive command
on the wrong box, and it's specific to this product rather than borrowed from a
design system.

**Typography rule:** machine-generated strings are mono — hostnames, ports,
usernames, fingerprints, paths, file sizes. Human labels and prose are sans. This
is a real rule with a real boundary, not a vibe, and it makes the UI legible in a
way that picking two nice fonts does not. Give the mono face the personality
(it *is* the product) and keep the sans neutral.

Derive the single accent colour from the logo so the app and the mark agree.

### C1. Native window treatment

Highest impact-per-line change in this track. Currently the app reads as a web view
in a box.

- **macOS:** `titleBarStyle: "Overlay"`, `hiddenTitle: true`, traffic lights inset,
  tab bar occupying the titlebar strip. Use Tauri's built-in `windowEffects`
  configuration with `sidebar`.
- **Windows:** include Tauri's built-in `mica` effect as the platform fallback.
- **Linux:** no equivalent; use a flat solid and don't fake it.

Tauri's transparent macOS window support requires `macos-private-api`. That is
acceptable for direct distribution but prevents Mac App Store submission; this
trade-off must stay documented until a public-API replacement is chosen.

### C2. Collapsible sidebar

Three states, not two:

| State | Width | Trigger |
|---|---|---|
| Expanded | 260px | default |
| Rail | 52px | `Cmd/Ctrl+B`, or drag below ~180px |
| Drawer | overlay | viewport < 768px (existing breakpoint) |

Rail shows the logo mark, host favicons/initials tinted with `Host.color`, and the
add-host button. Tooltips on hover. Animate width with a CSS transform, not a
layout-affecting property, and call `fitAddon.fit()` on transition end — not during
— or every keystroke reflows the terminal mid-animation.

Persist the state in `localStorage`. **This does not violate hard rule 4** — that
rule is about secrets, and a sidebar width is not one. Note it in the commit
message so nobody "fixes" it later.

### C3. Command palette

`Cmd/Ctrl+K`, fuzzy over hosts and actions (connect, open SFTP, new local tab,
lock vault, import config). This is what makes a collapsed sidebar actually usable
rather than just smaller, so it ships in the same pass. Reuse the existing generated
TS types for the host list; no new IPC surface needed.

### C4. Density and detail

Terminal users want compact: 28–32px list rows, not 44. Elevation from hairline
borders rather than shadows. Reserve motion for state changes that carry meaning —
connecting, transfer progress, lock — and respect `prefers-reduced-motion`.
Visible keyboard focus on everything.

**Acceptance:** sidebar collapses via keyboard and pointer and persists across
restart; terminal reflows exactly once per transition; host colour visible in rail,
tab, and viewport hairline; palette opens and connects to a host without the mouse;
everything still collapses correctly below 768px.

## Track D — Logo everywhere

Bundle icons in `apps/tauri/src-tauri/icons/` are already canonical. What's missing
is in-app usage.

1. **Add an SVG mark** at `apps/ui/src/assets/tethra.svg`. The bundle icons are
   raster and won't scale cleanly in-app.
2. **`<Logo>` component** with `variant="mark" | "lockup"` and a size prop. The
   rail needs mark-only, the lock screen needs the full lockup — this is why C2
   and D are in the same milestone.
3. **Placements:** sidebar header (lockup expanded, mark in rail), `VaultGate`
   lock screen, empty state when no tabs are open, About dialog, dev-server favicon.
4. **Derive the accent** in C0 from the mark's primary colour.
5. **README** header once the repo goes public.

**Acceptance:** no placeholder or default Tauri iconography reachable anywhere in
the app, dock/taskbar, or dev tab.
