## What's actually wrong (from the screenshots)

### Bug 1 — `CFBundleName` is still the crate name

Screenshot 5 shows the app menu reading **"Hide tethra ⌘H"** and **"Quit tethra ⌘Q"**
— lowercase. macOS builds those two strings from `CFBundleName`, not from
`productName` or the menu title. So the M5.5 rename set `productName` but left
`CFBundleName` on the Cargo package name.

Fix in `tauri.conf.json` → `bundle.macOS`, or via an `Info.plist` override:

```json
{ "bundle": { "macOS": { "bundleName": "Tethra" } } }
```

Verify by rebuilding and reopening the app menu. Do **not** touch `identifier` —
that's still pinned to the vault-path constant from M5.5 §A0.

### Bug 2 — the WebView context menu is leaking

Screenshot 4 is the raw WKWebView menu inside a terminal: Show Writing Tools,
Spelling and Grammar, Substitutions, Transformations, Paragraph Direction,
AutoFill, Inspect Element. None of it applies. "Transformations" would silently
smart-quote text destined for a shell.

There is no Tauri config flag for this. The supported path is a JS `contextmenu`
listener, injected from Rust via `WebviewWindowBuilder::initialization_script` so
it applies before first paint. On Windows you can additionally set WebView2's
`AreDefaultContextMenusEnabled = false` through `with_webview`.

**Suppress globally, then build real menus per surface:**

| Surface | Items |
|---|---|
| Terminal | Copy, Paste, Copy as markdown block, Clear, Split right/down, Rename tab, Close |
| Terminal (selection) | Copy, Paste, Search selection, Send to Assist |
| OSC 133 block | Copy command, Copy output, Copy both, Rerun, Rerun on… |
| Host card / sidebar | Terminal, Files, Agent, Edit, Duplicate, Copy SSH command, Delete |
| SFTP row | Open, Download, Rename, Delete, Copy path, Copy remote URL |
| Tab | Close, Close others, Close to the right, Move to new window, Detach |

Keep an `Inspect Element` item in dev builds only — `#[cfg(debug_assertions)]`.

Build these with your existing Radix `ContextMenu` primitive so they inherit the
app's tokens. That is the whole point: the menu should look like Tethra, not like
Safari.

### Bug 3 — the menu bar is nearly empty

The bar shows only **Tethra / Edit / Window**. There's no File, View, Terminal,
Go, or Help, and Edit is the default stub. Every real macOS app has these, and
their absence is a large part of why the app reads as a web app in a frame.

Build a proper menu with Tauri v2's menu API. **Every item must call the same
command the UI calls** — the menu is a second entry point to existing actions, not
a parallel implementation.

```
Tethra   About, Settings… ⌘,, Lock Vault ⌃⌘L, Check for Updates…, Services, Hide, Quit
File     New Terminal Tab ⌘T, New Local Tab ⇧⌘T, New Window ⌘N, Open Project… ⌘O,
         Import ~/.ssh/config…, Close Tab ⌘W
Edit     Undo, Redo, Cut, Copy ⌘C, Paste ⌘V, Select All, Find… ⌘F
View     Toggle Sidebar ⌘B, Launcher ⌘⎋, Split Right ⌘D, Split Down ⇧⌘D,
         Zoom Pane ⇧⌘↩, Increase/Decrease Font, Appearance ▸
Terminal Clear ⌘K, Reset, Assist ⌘I, Rerun Last Block, Broadcast to… (M13)
Go       Command Palette ⌘K, Next/Previous Tab, Hosts ▸, Projects ▸, Running ▸
Window   Minimize, Zoom, Bring All to Front, <window list>
Help     Documentation, Keyboard Shortcuts, Report an Issue, Release Notes
```

Two conflicts to resolve deliberately: `⌘K` is both palette and clear-terminal
(give palette `⌘K`, clear `⌘⇧K` — terminal users expect `⌘K` to clear, but the
palette is more frequent here), and `⌘W` must close a *tab*, only closing the
window when it's the last tab.

Windows gets no menu bar. Those commands surface in the titlebar overflow (`…`)
and the palette. Never render a fake macOS-style menu bar on Windows.

## Track A — Settings, in one place

You said "have all the settings in one." Right now they're scattered across the
`…` overflow, the vault modal, and Assist config. Build one Settings surface,
opened by `⌘,` on macOS and `Ctrl+,` on Windows.

**Shape:** a modal on macOS (native-feeling for `⌘,`), a full page on Windows
(Fluent apps use a Settings *page*, not a dialog). Same React tree, two shells.

| Section | Contents |
|---|---|
| **General** | Startup behavior, default landing (Launcher/last session), update channel, check-for-updates |
| **Appearance** | Theme (light/dark/system), accent, **window material + opacity**, density, chrome style |
| **Terminal** | Font family/size/line height, ligature toggle, cursor style/blink, scrollback limit, bell, copy-on-select, `Option`-as-`Meta` |
| **Shell** | Default local shell, login-shell toggle, env overrides, shell-integration mode per M7 |
| **Vault** | Auto-lock timeout, lock-on-sleep, change master password, keyring recovery, re-key |
| **Sync** | Backend, interval, sync host, last sync, `sync_secret` defaults, join/reset |
| **AI providers** | The M11.1 preset → key → Test → model flow |
| **Agents** | M11.2 catalog, installed state, custom presets, BYOK env bindings |
| **Keyboard** | Full keymap, searchable, rebindable, conflict detection |
| **Advanced** | Logging level, catalog source override, reset layout, export diagnostics |

Two rules that make it feel finished: every setting is reachable from the palette
by name (`⌘K` → "scrollback"), and every setting has a visible default with a
one-click revert.

## Track B — Materials and transparency

This is the iTerm2/Warp quality you're missing. It's also the track most likely to
tank performance if done naively, so the caveats matter more than the API.

### The library

`window-vibrancy` (Tauri org, ~2.1M downloads/month). Required setup, all three
mandatory or you get a black window:

1. `"transparent": true` in the window config
2. `"macOSPrivateApi": true` in `tauri.conf.json`
3. `html, body { background: transparent }`

### ⚠️ The performance matrix is not uniform

From the crate's own support table:

| Function | Platforms | Caveat |
|---|---|---|
| `apply_vibrancy` | macOS 10.10+ | Clean |
| `apply_mica` | Windows 11 | **Clean — use this** |
| `apply_acrylic` | Windows 10/11 | Bad perf resizing/dragging on Win10 v1903+ and Win11 22000 |
| `apply_blur` | Windows 7/10/11 22H1 | Bad perf resizing/dragging on Win11 22621+ |
| — | Linux | Unsupported; compositor-controlled |

So: **Mica on Windows 11, nothing on Windows 10, nothing on Linux.** Do not ship
acrylic or blur as a Windows default — dragging a terminal window that stutters is
worse than an opaque one. Offer them as opt-in "may affect performance" choices.

Detect the build at runtime (`windows_version::OsVersion::current()`, Win11 is
build ≥ 22000) rather than assuming.

### ⚠️ `macOSPrivateApi` has consequences

The name is literal — it enables private API use. That closes the Mac App Store
as a distribution channel. Irrelevant if you're distributing a signed `.dmg`
directly, which you are, but decide it consciously now rather than discovering it
later.

### ⚠️ Verify transparency against the WebGL terminal renderer

Transparent backgrounds under xterm.js need `allowTransparency: true` and an
`rgba()` theme background. This interacts with the WebGL renderer and with your
M12 scroll-jump workarounds in ways I could not confirm from documentation.

**Spike this before committing to the design.** Build one window with vibrancy on
and a terminal running `htop` and a large `cat`, and check: does WebGL still
composite correctly, does the canvas fallback trigger, does throughput regress.
If WebGL and transparency conflict, the answer is transparency on chrome only —
sidebar, titlebar, launcher, modals — with the terminal viewport kept opaque.
That is what most terminals actually do anyway, and it looks correct.

### Expose it as a setting, not a constant

Appearance → Window material: `Opaque | Vibrant | Custom`, plus an opacity slider
(85–100%) and a blur radius where supported. Terminal background opacity should be
a **separate** control from chrome opacity. Ship **Opaque as the default** and let
people opt in.

## Track C — Windows as a first-class target

You're right that it's a copy-paste of the Mac build. The fix is a
`ChromeStyle` abstraction, not per-component `if (isWindows)` branches scattered
through the tree.

```ts
type ChromeStyle = 'mac' | 'win' | 'linux';
```

Resolve once at startup, put it on a context, and let layout components read it.

### What actually differs

| | macOS | Windows 11 |
|---|---|---|
| Window controls | Traffic lights, **left**, native, inset | Caption buttons, **right**, 46px wide |
| Titlebar | Overlay, `hiddenTitle`, content bleeds up | Extended client area, Mica through it |
| Corner radius | System-drawn | System-drawn (Win11); don't fake it |
| UI font | SF Pro (system default) | **Segoe UI Variable**, fall back to Segoe UI |
| Icons | Lucide is fine | **Segoe Fluent Icons** for window/system glyphs |
| Menus | Menu bar | Titlebar overflow + palette |
| Settings | `⌘,` modal | `Ctrl+,` full page, Fluent SettingsRow cards |
| Accent | App accent | Honor the **system accent color** |
| Scrollbars | Overlay, auto-hide | Thin Fluent style |
| Shadows/elevation | Soft, large | Tighter, Fluent depth ramp |

Microsoft's own guidance is explicit that apps specifying Segoe UI should now
specify **Segoe UI Variable**, and that titles should use Segoe UI Variable where
available. It degrades gracefully on Windows 10.

### ⚠️ The trap: `decorations: false` breaks Snap Layouts

This is the single biggest Windows-native mistake and it's easy to ship without
noticing. Disabling decorations for a custom titlebar means **hovering the
maximize button no longer shows the Windows 11 Snap Layout flyout**. It's a
long-standing Tauri issue. Windows users use this constantly and will read its
absence as the app being broken.

The fix is a native child HWND overlay returning `HTMAXBUTTON` from
`WM_NCHITTEST`, which makes the OS produce the real flyout — no input simulation.
Three crates do this; pick one:

| Crate | Notes |
|---|---|
| **`tauri-plugin-decoration`** | Broadest: Win11 snap, macOS traffic-light inset, transparency, Linux themed icons. Cross-platform, so one dependency covers both your targets |
| `tauri-plugin-frame` | Windows-only, opinionated, auto-injects scripts, exposes `--tauri-frame-controls-width` CSS var, light/dark hover colors |
| `tauri-plugin-snap-layout` | Minimal; tracks an element ID and overlays it |

`tauri-plugin-decoration` is the recommendation since it also handles the macOS
traffic-light inset you need for the overlay titlebar — one crate, both platforms.

Whichever you pick, the `--tauri-frame-controls-width` pattern matters: your
titlebar's right padding must be driven by that variable, or the search box will
sit under the caption buttons at some DPI.

### Also verify on Windows

Window *repositioning* has known bugs with `decorations: false` on Windows 11
(distinct from resizing). Test drag-to-move, drag-to-snap, double-click-to-maximize,
and `Win+Arrow` explicitly.

## Track D — Visual design

Reading the screenshots as a design review, not a bug list.

**The core problem: it looks like default shadcn dark.** Neutral grays, a
medium blue accent, 8px radii, evenly-weighted buttons. It's competent and it's
what every AI-assisted dev tool shipped this year. Nothing about it says
*terminal*, and nothing says *Tethra*.

Specific issues:

1. **`Host.color` is doing nothing.** It's a 1px top border on the card, invisible
   at a glance. M5.5 §C0 specified it as ambient identity — the collapsed rail
   indicator, the active tab underline, a hairline on the terminal viewport. Right
   now you have three hosts in three colors and you cannot tell which machine
   you're on without reading. Fix this first; it's the highest ratio of identity
   to effort in the whole app, and it's a safety property.

2. **Too many buttons per host card.** Terminal / Files / Agent as three
   equal-weight buttons × N hosts is a wall of chrome. Make the card itself
   clickable for the primary action, and reveal secondary actions on hover or in
   the (now custom) context menu. The launcher should feel calm.

3. **Type hierarchy is inverted.** "Resume where you left off" is set larger than
   anything it introduces, and it introduces an empty region. Section headers
   (`PROJECTS 0`, `HOSTS 3`) are doing the real navigational work — let them.
   Reduce the hero, raise the sections.

4. **The M5.5 mono/sans rule isn't enforced.** Hostnames and `user@host` strings
   are mono in some places and sans in others. Machine-generated strings — hosts,
   ports, paths, fingerprints, sizes — should always be mono. It's a real rule
   with a real boundary and it costs nothing.

5. **Empty states are bare sentences.** "No projects yet" with no affordance. The
   launcher with zero projects should offer *New project* as a real target, and
   with zero hosts should offer *Import ~/.ssh/config* as the primary action.

6. **The accent is generic.** Derive it from the logo mark (M5.5 §D4) and on
   Windows honor the system accent instead. Two lines of work, immediate
   differentiation.

7. **Toolbar icons are unlabeled and ambiguous.** Six glyphs in the top right with
   no tooltips and no grouping. Add tooltips with shortcuts, and separate
   destructive/state actions (Lock) from view actions (Split, Layout).

**Where to spend boldness:** the terminal is the product, so let the chrome
recede and make the *blocks* the visually interesting element. You already parse
OSC 133. Failed-block gutters, hover affordances, and a subtle running-command
indicator will read as "modern terminal" far more than any amount of gradient.
