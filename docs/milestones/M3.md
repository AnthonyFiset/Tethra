# M3 encrypted vault

M3 replaces the M2 environment-host bootstrap with a local encrypted vault.
Hosts and password identities are stored as independently encrypted SQLite rows.
The vault master key is wrapped with Argon2id + XChaCha20-Poly1305; an optional
recovery key lives in the OS keyring and never stores the vault key itself.

## Cryptography

| Piece | Choice |
| --- | --- |
| KDF | Argon2id (`m=65536 KiB`, `t=3`, `p=4`), parameters stored in the vault header |
| Key separation | HKDF-SHA256 labels `vault-enc-v1` / `vault-auth-v1` |
| Item encryption | XChaCha20-Poly1305, AAD = `item_id \|\| version` (LE) |
| Key hygiene | `zeroize` / `ZeroizeOnDrop` on vault keys and temporary buffers |

## Desktop lifecycle

- Explicit lock from the UI
- Idle auto-lock (15 minutes by default, enforced in Rust)
- Best-effort lock on suspend / session lock
- Locking closes SSH sessions, clears host-key prompts, emits `vault-status` /
  `vault-locked`, and zeroizes key material

Recovery unwraps the vault key with the keyring-held recovery key, then rewraps
it under a newly supplied master password. Password changes also rewrap only the
vault key; item rows are not re-encrypted.

If the OS keyring is unavailable, vault creation can continue without recovery
after an explicit UI warning.

## Run locally

```bash
cd apps/tauri/src-tauri
npx --prefix ../../ui tauri dev
```

On first launch, create a vault and add hosts through the UI. Password fields are
uncontrolled inputs: values are read once, sent to Rust, and cleared from the DOM
immediately. Passwords are never kept in React state or browser storage.

## IPC

[`apps/ui/src/lib/ipc.ts`](../apps/ui/src/lib/ipc.ts) remains the only frontend
module that imports Tauri APIs. Vault and host commands return only status, IDs,
and non-secret metadata (`hasPassword`, never the password).
