# M6 Sync

M6 syncs **encrypted host metadata** across devices. Password identities stay
`local_only` on each machine — you unlock with the same master password, then
re-enter host passwords (or use local keys) per device.

## Backends

| Backend | When to use |
|---|---|
| **HTTP** (`tethra-sync-server`) | ThinkPad / always-on Linux box over Tailscale |
| **File** | Dropbox, iCloud Drive, Syncthing, or a shared folder |

Conflicts resolve last-write-wins on item `version`, then `updated_at`, then keep local on an exact tie.

## ThinkPad over Tailscale

On the Ubuntu host:

```bash
cargo install --path crates/sync-server
# or: cargo build -p tethra-sync-server --release

tethra-sync-server \
  --data-dir ~/tethra-sync \
  --listen 0.0.0.0:8787 \
  --token 'pick-a-long-secret'
```

Keep the process up with systemd, `tmux`, or similar. Tailscale provides the
transport and ACLs; the optional token stops casual LAN misuse.

On Mac / Windows / Mac Mini:

1. Unlock Tethra with the **same master password** as the first device.
2. Open **Vault sync** (⋯ menu or ⌘K → “Vault sync”).
3. Choose **HTTP server**, set URL to `http://<tailscale-hostname>:8787`, paste the token.
4. Click **Sync now**.

Host rows appear; password fields stay empty until you save credentials locally.

## Shared folder

Same dialog → **Shared folder** → pick a directory every client can write
(Dropbox / Syncthing / etc.). Layout on disk:

```
manifest.json
vault-header.json
items/<uuid>.json
```

## Secret boundary

- Only opaque ciphertext blobs leave the device.
- Sync never moves password identity rows.
- The HTTP token is a shared bearer (base64 in `Authorization`); it is not a vault key.
- Prefer Tailscale + token; do not expose the sync port on the public internet.

## Desktop installer releases

Push a version tag to build installers via GitHub Actions:

```bash
git tag v0.1.0
git push origin v0.1.0
```

The **Release** workflow produces:

- macOS `.dmg` (Apple Silicon + Intel)
- Windows `.exe` (NSIS)
- Linux `.deb` / AppImage
- `tethra-sync-server` Linux binary artifact

Draft releases are created automatically; review assets before publishing.
You can also run the workflow manually from the Actions tab (`workflow_dispatch`).

Unsigned personal builds are expected until Apple/Windows signing certs are configured.
