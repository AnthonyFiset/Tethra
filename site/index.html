How it works

Connect. Launch. Walk away.

01

Connect your machines

Add hosts with a password or SSH key — or import ~/.ssh/config in one click. Everything lands in an encrypted vault only you can open.

02

Launch any agent

Claude Code, Codex, Gemini, aider — pick from the catalog and Tethra installs what's missing on the host for you. Every session runs inside tmux.

03

Leave — it keeps going

Close the tab, close the laptop. The session survives on the host, your vault syncs to your other devices, and Tethra notifies you when the agent needs you.

Features

An SSH client built for the agent era.

Persistent sessions

tmux and zellij under the hood. Sessions outlive the app, the connection, and the machine you started them from.

Agent notifications

Know the moment an agent is waiting for input, finishes, or fails — even in sessions you've detached from.

Encrypted vault

Hosts, keys, and passwords sealed with your master password. Argon2id + authenticated encryption; nothing readable at rest.

Sync without trust

Devices sync through a server that only ever sees ciphertext. Keys and passwords sync only if you opt in — per item.

Self-host in one binary

Run the sync server on a Raspberry Pi, a VPS, or Tailscale. One Rust binary, no database, free forever.

Full SSH toolkit

SFTP with resumable transfers, ssh-config import, host-key verification, command blocks — the table stakes, done right.

Security model

The sync server can't read anything. By design.

✓Ciphertext-only sync. The server stores opaque encrypted rows. There is nothing to leak.
✓Keys never leave the device unless you explicitly opt a key into sync — and then only as ciphertext.
✓Vault-derived device auth. A new device needs your master password, not a pasted token.
✓Open source, Apache-2.0. The client, the server, the crypto — read every line.
